# ⚠ These questionnaires reflect rubric v1.0 — v1.5 deltas

The `Section-*.md` packets in this folder were written against *Rubric for
Human Review of AI.docx* v1.0 (2026-08-14). The rubric is now **v1.5
(2026-08-29)** — transcribed in full in
`src/aireadiness_evidence/rubric_defs.yaml`, which is the source of truth. The
merged-question format here ("Q0.1 = 0.a + 0.b") conflicts with v1.5's
criterion-level gates, so these packets need an owner decision: regenerate
them per-criterion, or retire them in favor of `ai-ready-review.html`.

Until then, anyone grading from these packets must apply the following v1.5
changes on top.

## New scoring machinery (applies everywhere)

- **Gates** (evaluated independently of the score): 0.a must score **2**;
  0.b, 0.c, 0.d, all of section 1, all of section 4, and 2.c must score
  **above 0**. Any failure marks the domain and the overall result
  **"Gating FAIL"** (the score is still computed). N/A is not permitted on a
  gating criterion. *The merged questions here cannot express the 0.a = 2
  gate — score 0.a separately if you use these packets.*
- **Overall score** = unweighted average of the seven domain percentages
  (not raw points / 56).
- **Dependency caps**: 1.b ≤ 1.a and 6.a ≤ 2.c.
- **N/A** applies at criterion level only when *every* element is
  inapplicable; otherwise score the applicable elements.
- **Expert adjudication** consolidated to: 2.c, 2.d, 2.e, 3.a, 4.a, 4.c, 5.c.
- **"Sustainable repository"** now has a glossary definition (assigns PIDs,
  independent metadata, long-term resources — NIH/EBI/DDBJ/ICPSR/GREI/
  Software Heritage; explicitly **excludes** departmental servers, S3/GCS,
  Google Drive, Box). The v1.0 re3data/FAIRsharing test is gone.

## Per-section rule changes

**Section 0** — 0.a: PID must resolve to a *specific version* and the deposit
be in a *sustainable* repository (see glossary; registry lookup dropped).
0.d: now has a middle grade — license present but not machine-readable (e.g.,
buried in a PDF) scores 1; a 2 requires the license/DUA *programmatically
linked* in the metadata (schema.org:license) with no AI/ML prohibition.

**Section 1** — 1.a: a 2 requires naming the exact data artifact, not just
the hospital/lab. 1.b: known provenance gaps / chain-of-custody breaks must
be explicitly disclosed (undisclosed gaps cap at 1); score capped at 1.a.
1.c: proprietary commercial software with a provider-website URI now counts
for 2.

**Section 2** — 2.b: non-tabular data is **no longer blanket N/A**; score
missing-value consistency in modality terms (absent channels, dropped leads,
corrupt slices, time-series gaps); N/A only when no representable missingness
exists; also asks whether the chosen statistics are domain-appropriate.
2.c: **now gating** (> 0); scored per format class ("for every format class
present in the deposit"). 2.d: two new elements — demographic/cohort
representativeness disclosure, and (for clinical data) admission-pattern /
site-selection bias; "state-vs-control" is now "case-vs-control". 2.e: asks
for a link to the specific QC protocol or software used.

**Section 3** — 3.a: score only datasheet existence/coverage; do **not**
re-score 2.d bias or 3.b use cases here. 3.c: hashes must be recorded in the
metadata that describes the dataset (metadata and data verifiably reference
each other).

**Section 4** — 4.a: retrospective data needs an explicit waiver/exemption
basis for secondary AI/ML use; prospective data needs consent language
explicitly covering downstream AI/ML training and commercialization; element
list is now IRB/REC protocol + governance-committee chair + ethics reviewer
and institution. 4.b: a 2 requires a PIA (or equivalent) for
high-sensitivity data — or a justified low-sensitivity determination — plus a
documented periodic re-identification-risk reassessment plan; the
confidentiality-code requirement moved wholly to 4.d. 4.c: rewritten around
"as open as possible, as closed as necessary"; where the modality can
synthesize/impersonate/re-identify (raw voice, personal genomes, face or
full-head imaging, dense longitudinal geolocation), the DUA must carry
explicit modality-specific prohibitions (no biometric synthesis, identity
cloning, discriminatory use); 0 now also covers controlled access with no
ethical framework. 4.d: 0 also applies when the declared level is not
enforced (controlled data retrievable without authorization, or authorized
users blocked) — this clause moved here from v1.0's 6.b.

**Section 5** — 5.a: raw/unprocessed data only; a 2 needs a
domain-appropriate repository + PID + retention commitment. 5.b: multi-domain
data in a recognized generalist repository (NIH GREI) can score 2, as can
single-domain data in a generalist when no specialist repository exists.
5.c: terms-of-access dropped from scoring — a 2 is a *linked, comprehensive*
DMP detailing long-term stewardship/maintenance/policy handling; linked but
thin = 1; none = 0.

**Section 6** — 6.a: conditioned on 2.c (a 1 is "schema present but no
populated vocabulary bindings"; capped at 2.c's score). 6.b: the
enforcement-failure "also 0" clause moved out (to 4.d). 6.c/6.d: unchanged.
